# 한국 내수 세탁기 카탈로그 트러블슈팅 보고서

작성일: 2026-11-11

## 1. 긴 PDF 처리 중 Neon 연결 종료

### 발생한 오류 및 원인 파악

- 오류: `sqlalchemy.exc.OperationalError: server closed the connection unexpectedly`
- 발생 위치: 공식 PDF 다운로드·텍스트 추출을 마친 뒤 모델-문서 연결을 조회하는 단계
- 원인: 수백 쪽 PDF를 처리하는 동안 하나의 SQLAlchemy 세션과 Neon 연결을 계속 보유했습니다. 연결이 오랫동안 사용되지 않자 서버가 유휴 연결을 종료했고, 같은 세션으로 다음 쿼리를 보내면서 실패했습니다.
- 영향: 실패한 배치는 커밋되지 않았고, 직전 완료 배치까지의 데이터는 보존됐습니다.

### 해결 방법 제시

- 문서 ID·URL·형식만 메모리의 `DocumentTarget`으로 복사한 뒤 조회 세션을 즉시 닫았습니다.
- 네트워크 다운로드와 PDF 추출을 DB 연결 없이 수행하도록 순서를 바꿨습니다.
- 저장 직전에 새 세션을 열어 문서 ORM 객체를 다시 읽고, 한 배치만 커밋한 뒤 바로 닫도록 수정했습니다.
- `OperationalError`가 발생하면 전체 미커밋 배치를 롤백하고 새 연결로 최대 3회 재시도합니다.
- 저장은 문서 ID와 안정 키 기반의 멱등 처리라 같은 배치를 다시 실행해도 중복 행이 생기지 않습니다.

수정 핵심 흐름:

```python
# 다운로드와 추출 단계에서는 DB 연결을 사용하지 않습니다.
results = await download_and_extract(batch)

# 저장할 때만 새 세션을 짧게 열고 닫습니다.
db = SessionLocal()
try:
    store_results(db, results)
    db.commit()
finally:
    db.close()
```

### 재발 방지 대책

- 배치별 새 세션 사용을 검증하는 `test_store_batch_uses_short_fresh_session` 회귀 테스트를 추가했습니다.
- 공용 DB 엔진의 `pool_pre_ping=True`와 배치 자체 재시도를 함께 사용합니다.
- 진행 JSON과 DB 커밋을 배치 단위로 갱신해 프로세스가 중단돼도 `pending` 문서만 다시 처리합니다.

## 2. CFF Type1 글꼴 PDF 추출 경고

### 발생한 오류 및 원인 파악

- 경고: `fontTools is required to fully parse the encoding of a CFF Type1 font`
- 원인: 일부 LG 공식 설명서가 CFF Type1 글꼴을 포함하지만 초기 환경에는 선택 보조 라이브러리인 `fontTools`가 없었습니다.
- 영향: PDF 자체는 열렸지만 일부 글자의 인코딩을 완전히 해석하지 못해 사용법 누락 가능성이 있었습니다.

### 해결 방법 제시

- `fonttools>=4.55,<5`를 애플리케이션 의존성에 추가했습니다.
- `uv.lock`을 갱신하고 `fonttools 4.68.0` 설치를 확인한 뒤 체크포인트부터 재개했습니다.

### 재발 방지 대책

- 새 개발 환경도 `uv sync --extra dev` 한 번으로 동일한 PDF 보조 의존성을 설치합니다.
- 추출 결과는 계속 `needs_review`로 저장해 라이브러리 설치 여부와 관계없이 자동 확정하지 않습니다.

## 3. 제목만 사용법으로 저장된 초기 추출 규칙

### 발생한 오류 및 원인 파악

- 초기 표본 10개 HTML 문서에서 `세탁 코스`, `옵션` 같은 짧은 제목이 사용법 문장으로 저장됐습니다.
- 원인은 키워드 포함 여부만 보고 문장의 길이와 행동 지시 형태를 충분히 검사하지 않은 것이었습니다.

### 해결 방법 제시

- 짧은 문장은 `하세요`, `마세요`, `됩니다`, `누르세요` 같은 실제 절차 표현이 없으면 제외했습니다.
- `--reprocess` 옵션을 추가해 기존 자동 생성 `needs_review` 행 67개만 삭제·재생성했습니다.
- 사람이 검토해 확정한 행은 재처리 시 삭제하지 않습니다.

### 재발 방지 대책

- 제목 문구와 예상 시간 문구가 제외되는 단위 테스트를 추가했습니다.
- 대량 처리 전에 소량 표본을 먼저 확인하고, 전체 결과도 공식 URL·페이지·근거 문장과 함께 표본 검수합니다.

## 4. 재처리 중 동일 고유 키 충돌

### 발생한 오류 및 원인 파악

- 오류: `UniqueViolation: duplicate key value violates unique constraint uq_catalog_usage_item`
- 원인: 같은 트랜잭션에서 기존 `needs_review` 행을 삭제하고 같은 안정 키의 새 행을 추가할 때 SQLAlchemy가 INSERT를 DELETE보다 먼저 보낼 수 있었습니다.
- 영향: 해당 배치 전체가 롤백됐으며 기존 행은 보존됐습니다.

### 해결 방법 제시

- 기존 자동 행을 `delete()`한 직후 `db.flush()`를 호출해 DELETE가 먼저 DB에 반영되도록 순서를 고정했습니다.
- 이후 같은 안정 키의 새 행을 추가하고 배치 전체를 커밋합니다.

### 재발 방지 대책

- 같은 모델·문서·안정 키를 재처리해도 정확히 한 행만 남는 회귀 테스트를 추가했습니다.
- 고유 제약은 그대로 유지해 애플리케이션 실수가 생겨도 중복 데이터가 커밋되지 않게 했습니다.

## 5. Windows 콘솔의 CP949 출력 오류

### 발생한 오류 및 원인 파악

- 품질 표본 출력 중 `UnicodeEncodeError: 'cp949' codec can't encode character`가 발생했습니다.
- 설명서 문장에 CP949가 표현하지 못하는 기호가 포함됐고, Windows 콘솔 기본 인코딩으로 JSON을 출력하려다 실패했습니다.

### 해결 방법 제시

- 검수 JSON은 `ensure_ascii=True`로 출력해 콘솔과 무관하게 유니코드 이스케이프로 확인했습니다.
- 한글 포함 여부는 셸 정규식 대신 문자 코드 범위 `0xAC00`~`0xD7A3`으로 계산했습니다.

### 재발 방지 대책

- 콘솔 출력용 진단 결과는 ASCII 안전 형식을 사용하고, 실제 DB 문자열은 UTF-8/Unicode로 그대로 보존합니다.
- 화면 출력 실패와 DB 저장 실패를 분리해 판단합니다.

## 6. 로컬 검증 환경의 권한 오류

### 발생한 오류 및 원인 파악

- `npm run build` 내부의 `uv run`이 격리된 사용자 캐시에 임시 파일을 쓰지 못했습니다.
- Windows `TestClient`와 `asyncio.run()`은 내부 로컬 소켓을 만들지만 격리 환경에서 해당 소켓 생성이 막혀 테스트가 멈췄습니다.
- pytest의 시스템 임시 폴더도 격리 환경에서 쓰기 권한이 없어 `tmp_path` 생성이 실패했습니다.

### 해결 방법 제시

- 빌드 로직은 같은 가상환경의 `.venv\Scripts\python.exe -m backend.build`로 실행해 통과를 확인했습니다.
- HTTP·asyncio 테스트는 로컬 소켓 권한이 있는 검증 환경에서 실행했습니다.
- 새 테스트의 진행 파일은 프로젝트 내부 `.tmp`를 사용하고 테스트 종료 후 삭제하도록 바꿨습니다.

### 재발 방지 대책

- 코드 실패와 샌드박스 권한 실패를 출력과 스택 덤프로 구분합니다.
- CI와 개발 PC에서는 Runbook의 표준 `uv run pytest`, `npm run build` 명령을 사용합니다.
