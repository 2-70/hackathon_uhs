# 트러블슈팅 보고서: Python 실행 파일 확인 실패

## 발생한 오류 및 원인 파악

- `python --version`과 `python -m pip show ...` 실행 시 `C:\Users\wooji\AppData\Local\Microsoft\WindowsApps\python.exe`를 시작하지 못했습니다.
- 현재 저장소에 문제가 생긴 것이 아니라, Windows의 Python Store 별칭이 실제 Python 런타임을 가리키지 않는 환경 문제로 판단했습니다.

## 해결 방법 제시

- 먼저 `py --version`, `uv --version`, `where.exe python`, `where.exe py`로 사용할 수 있는 Python 실행기를 확인합니다.
- 실행 가능한 런타임이 있으면 이후 설치·테스트 명령을 해당 실행기로 통일합니다.
- 현재 확인 단계에서는 저장소 코드를 수정하지 않았습니다.

## 재발 방지 대책

- 실행 문서에 Python 버전 확인 명령과 가상환경 생성 명령을 함께 기록합니다.
- 서버 실행 전 `python --version` 또는 프로젝트에서 정한 실행기 명령이 정상 동작하는지 확인합니다.
- 실제 Python 런타임이 없는 경우에는 의존성 설치나 테스트를 성공했다고 표시하지 않고, 미검증 상태로 명확히 남깁니다.

## 추가 오류: uv 캐시 경로 접근 거부

### 발생한 오류 및 원인 파악

- `uv sync --extra dev` 실행 중 샌드박스 외부의 `%LOCALAPPDATA%` 하위 uv 캐시에 임시 파일을 저장하지 못했습니다.
- uv 자체와 관리형 Python 경로는 확인되었지만, 현재 작업 환경에서 외부 캐시 쓰기 권한이 없어 Python 인터프리터 확인 단계가 중단되었습니다.

### 해결 방법 제시

- `UV_CACHE_DIR`을 저장소 내부의 `.uv-cache`로 지정한 뒤 같은 명령을 다시 실행합니다.
- 저장소 내부 캐시와 관리형 Python 폴더는 `.gitignore`에 추가해 커밋되지 않게 합니다.
- 재시도 명령은 PowerShell 기준 `$env:UV_CACHE_DIR = Join-Path (Get-Location) '.uv-cache'; uv sync --extra dev`입니다.

### 재발 방지 대책

- 샌드박스 환경에서는 처음부터 프로젝트 내부의 쓰기 가능한 캐시 경로를 사용합니다.
- 의존성 캐시는 소스가 아니므로 Git에서 제외합니다.
- 캐시 경로 변경 후에도 실패하면 권한 문제가 아닌 Python 설치 또는 네트워크 문제인지 각각 분리해 기록합니다.

## 추가 오류: Windows 임시 폴더 접근 거부

### 발생한 오류 및 원인 파악

- 프로젝트 내부 캐시를 사용하자 uv가 CPython 3.14.7을 찾고 `.venv` 생성까지 진행했습니다.
- 이후 샌드박스 외부 Windows 임시 폴더의 `uv-trampoline-*.exe` 리소스를 갱신하는 단계에서 접근이 거부되었습니다.

### 해결 방법 제시

- 저장소 내부에 `.tmp`를 만들고 `TEMP`와 `TMP`를 해당 절대 경로로 지정합니다.
- `UV_CACHE_DIR`도 앞선 해결책처럼 저장소 내부 `.uv-cache`를 계속 사용합니다.
- 수정된 실행 환경에서 `uv sync --extra dev`를 다시 실행합니다.

### 재발 방지 대책

- 샌드박스에서 uv를 실행할 때 캐시뿐 아니라 임시 폴더도 쓰기 가능한 프로젝트 경로로 지정합니다.
- `.tmp`는 실행 산출물이므로 `.gitignore`로 제외합니다.
- 부분 생성된 `.venv`는 수동 삭제하지 않고 uv가 정상 상태로 동기화하도록 합니다.

## 추가 오류: 불완전한 가상환경

### 발생한 오류 및 원인 파악

- 앞선 uv 실행이 `.venv` 생성 도중 중단되어 Python 실행 파일이 없는 불완전한 가상환경이 남았습니다.
- uv는 기존 `.venv`를 정상 환경으로 판단할 수 없어 이후 동기화를 중단했습니다.

### 해결 방법 제시

- `.venv`의 절대 경로가 현재 저장소 내부인지 확인합니다.
- 이번 작업에서 생성된 불완전한 `.venv`만 제거한 뒤, 프로젝트 내부 캐시·임시 경로를 지정한 상태에서 uv가 새로 생성하도록 합니다.

### 재발 방지 대책

- 의존성 동기화가 실패한 경우 `.venv/Scripts/python.exe` 존재 여부를 먼저 확인합니다.
- 불완전한 환경만 정확한 절대 경로로 제거하며 저장소나 사용자 문서 같은 넓은 경로는 삭제 대상으로 사용하지 않습니다.
