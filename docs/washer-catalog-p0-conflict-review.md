# 15년 세탁기 카탈로그 PRD와 기존 P0 충돌 검토

## 결론

신규 기능은 기존 계획 엔진을 교체하지 않고 `0004` 이후의 추가형 카탈로그·수집 이력 구조로 분리하는 것이 안전합니다. 모델 기본정보가 수집됐다는 이유만으로 계획 엔진의 `confirmed` 설정 또는 추천 가능 상태를 만들면 안 됩니다.

## 충돌과 처리 원칙

| 기존 P0 | 신규 요구 | 처리 원칙 |
| --- | --- | --- |
| `machine_models.machine_key` 단일 안정 키 | 자료원·지역·접미사별 정확한 모델 보존 | 기존 키와 ID를 유지하고 외부 식별자·지역 변형·출처 주장 테이블을 추가합니다. 기존 행의 키를 일괄 변경하지 않습니다. |
| 모델 행에 확인 상태 1개 | 실존·생산기간·코스 설정 상태 분리 | `catalog_only`, `care_settings_partial`, `recommendation_ready`를 별도 필드 또는 검증 테이블로 분리합니다. |
| `machine_courses/settings`가 추천 근거 | 대량 수집 모델 대부분은 기본정보만 있음 | 코스·동시 지원 설정이 confirmed인 모델만 기존 계획 엔진에 들어갑니다. 기본정보 수집기가 빈 코스나 추정 조합을 만들지 않습니다. |
| `duration_minutes` nullable 칼럼과 조회 응답 | 예상시간 기능 제외 | 칼럼은 migration 호환을 위해 유지하되 계획·설정검증 응답에는 사용하지 않습니다. 원문 시간은 출처 원문 보존용일 뿐 추천시간으로 노출하지 않습니다. |
| 모델 검색은 전체 배열 반환 | 대량 카탈로그 검색 | 기존 호출을 깨지 않는 전환 전략과 함께 페이지네이션·브랜드·지역·생산근거·추천상태 필터를 추가해야 합니다. |
| 공식 검증 시드 경로는 AI 담당 | 다중 공식 자료원 수집 | `backend/seed/verified/`를 수정하지 않고 공용 `backend/app/catalog_ingest/`와 별도 원문·체크포인트 저장 경로를 사용합니다. |
| 실제 Neon `0003` 적용 완료 | 대량 수집용 스키마 | 새 변경은 `0004` 이후 추가형 migration으로 작성하고 기존 사용자기기 FK와 LG 모델 ID를 보존합니다. |

## 시간 예측 확인

- 기존 계획 응답과 설정검증 응답은 예상 세탁시간을 생성하거나 반환하지 않습니다.
- `machine_course_settings.duration_minutes`는 nullable 하위호환 필드이며 현재 공식 LG 시드에서는 null입니다.
- 모바일에서 검색된 `remaining`은 남은 시간이 아니라 드럼에 더 넣을 수 있는 의류 수입니다.
- AI의 `estimated` 표시는 관리정보 추정 출처로, 세탁시간 예측과 다른 개념입니다.
- 따라서 승인 전 즉시 삭제할 코드는 없고, 신규 수집 구현에서 시간값을 추천·최적화 입력으로 연결하지 않으면 됩니다.

## 구현 승인 후 선행 결정

1. 공개 검색 API의 페이지네이션을 기존 무페이지 응답과 어떻게 병행할지 확정합니다.
2. 같은 모델명의 지역 접미사를 합치지 않는 안정 키 규칙을 테스트 예제로 먼저 고정합니다.
3. 생산기간 근거와 인증·판매일을 별도 주장 행으로 설계합니다.
4. 수집 실행·페이지 체크포인트·실패·재시도·콘텐츠 해시 테이블을 `0004`에 포함합니다.
5. 실제 자료원별 이용 조건·API/CSV·총건수·과거 범위를 확인한 뒤 어댑터를 구현합니다.

현재는 신규 기능 구현 승인 전이므로 collector 코드, `0004` migration, Neon 대량 적재를 시작하지 않았습니다.
